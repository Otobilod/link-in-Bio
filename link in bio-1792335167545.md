# Mini Link-in-Bio Builder Web App Prompt

## Role
Act as a senior JavaScript developer, UI/UX designer, and software tester. Build a polished, responsive Link-in-Bio Builder using HTML, CSS, and vanilla JavaScript.

## Objective
Create a web application that allows users to build attractive profile pages containing multiple links, customize their appearance, preview the result, and publish a shareable profile URL.

## Technical Requirements
- Use HTML5, CSS3, and vanilla JavaScript.
- Do not introduce a frontend framework unless explicitly necessary.
- Organize the code into clear, maintainable files.
- Ensure compatibility with Google Antigravity IDE Live Server.
- Use LocalStorage for the initial prototype.
- Keep the application architecture ready for future Supabase integration.
- Never expose secret API keys or service-role credentials in frontend code.

## Required Pages and Features

### 1. Dashboard
- Display the user's saved profiles.
- Provide buttons to create, edit, preview, and delete a profile.
- Show a clear empty state for new users.

### 2. Profile Editor
- Add a profile name, biography, and profile image.
- Add, edit, delete, enable, disable, and reorder links.
- Allow each link to have a title, URL, and optional icon.
- Validate URLs and form inputs.
- Provide a live preview that updates when the user edits their profile.

### 3. Design Customization
- Include at least five attractive themes.
- Allow background color, button color, text color, and button shape customization.
- Support mobile and desktop previews.
- Make the design accessible and responsive.

### 4. Public Profile Page
- Display the profile image, name, biography, social icons, and active links.
- Make every link clickable and open external websites safely.
- Provide a clean mobile-first layout.
- Display a friendly not-found page for unknown profiles.

### 5. Saving and Sharing
- Save and restore profiles using LocalStorage.
- Allow users to copy a profile URL.
- Clearly distinguish prototype-only local saving from genuinely public publishing.
- Do not pretend that a LocalStorage profile is available to other users or devices.

## Design Requirements
Use a modern, professional SaaS dashboard with attractive typography, consistent spacing, rounded cards, clear navigation, and polished interactions.

## Testing Requirements
- Test every button and form.
- Check for JavaScript errors.
- Verify that data persists after refreshing.
- Test adding, editing, deleting, and reordering links.
- Test invalid URLs and empty form fields.
- Verify responsive layouts at mobile and desktop widths.
- Ensure existing features continue working after changes.

## Development Workflow
1. Inspect the existing project before changing files.
2. Create a short implementation plan.
3. Build the minimum working version first.
4. Run and test it in Live Server.
5. Fix errors before adding advanced features.
6. Report all files changed and any remaining limitations.

---

> **Note:** Do not implement fake authentication, fake analytics, or fake cloud publishing. Clearly identify any feature that requires a backend.
> 
> *Begin by inspecting the project files and implementing the first working version.*
